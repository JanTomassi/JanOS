#+TITLE: JanOS Process Subsystem

This directory owns process execution. Process code must not be spread across
=kernel/kernel.c= or unrelated device drivers.

* Module Layout

** =process.c= / =process.h= - Process Objects

Owns the process table, PID allocation, process states, parent/child
relationships, file-descriptor ownership, and process lifetime.

Depends on: address spaces, kernel stacks, allocator.

Does not depend on: device drivers or the shell.

** =address_space.c= / =address_space.h= - Address Spaces

Owns creation and destruction of a process page directory, user mappings, and
the kernel-half mapping shared by processes.

Depends on: physical memory and VMM interfaces.

The user/kernel boundary is enforced here. Callers must not directly modify a
process page directory.

** =stack.c= / =stack.h= - Process Stacks

Owns allocation and release of kernel stacks and user stacks. It also provides
the initial user-stack layout for argc, argv, and future environment data.

Depends on: physical memory and address spaces.

** =context.c= / =context.h= - CPU Context

Owns the saved i386 register frame and the architecture-specific transition
between kernel code and ring 3. The i386 implementation belongs in:

#+BEGIN_EXAMPLE
kernel/process/arch/i386/context.c
kernel/process/arch/i386/context.s
#+END_EXAMPLE

This module owns =iret= entry, syscall return state, and the kernel-entry stack
frame. It must not own scheduling policy.

** =scheduler.c= / =scheduler.h= - Scheduler

Owns runnable queues, the current process, state transitions, and =yield=.
Start with cooperative scheduling. Timer-driven preemption is a later change.

Depends on: process objects and CPU context.

** =wait_queue.c= / =wait_queue.h= - Blocking

Owns queues used when a process waits for console input, files, or another
process. This is where =console_read()= will eventually wake a waiting process.

Depends on: process objects and scheduler.

* Dependency Direction

#+BEGIN_EXAMPLE
physical memory / VMM
          |
          v
address_space -> stack -> context
          |                  |
          v                  v
       process ---------> scheduler -> wait_queue
#+END_EXAMPLE

Lower layers must not call the scheduler. Device drivers may signal a
=wait_queue=, but they must not manipulate process internals.

* Initial Interfaces

Keep public interfaces in =kernel/include/kernel/process/= and implementation
files in this directory. Initial interfaces should be opaque where possible:

#+BEGIN_SRC c
struct process;

struct process *process_create(void);
void process_destroy(struct process *process);

void scheduler_init(void);
void scheduler_yield(void);
struct process *scheduler_current(void);
#+END_SRC

Do not expose page-directory internals, stack allocation details, or saved
register layout to general kernel code.

* Implementation Order

1. Define process states and ownership rules.
2. Implement address-space creation and destruction.
3. Implement kernel/user stack allocation.
4. Implement a kernel-only test process.
5. Implement i386 ring-3 entry and return.
6. Implement process exit and cleanup.
7. Implement cooperative scheduling and =yield=.
8. Add wait queues and connect console reads.

* Testing

- Unit-test PID allocation and state transitions where host testing is
  available.
- Boot a kernel-only process and verify cleanup after exit.
- Run a ring-3 program that attempts a kernel-only write and verify a fault.
- Run two cooperative processes and verify deterministic alternation.
- Verify that a blocked console reader wakes after Enter.
