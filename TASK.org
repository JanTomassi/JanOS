* Mission

Build the smallest end-to-end user experience for JanOS:

#+BEGIN_EXAMPLE
JanOS boots -> interactive console -> loads /bin/calc -> prefix calculator REPL
#+END_EXAMPLE

The calculator is a normal ring-3 ELF program. It is not a kernel module.

* Collaboration Rules

** Human responsibilities

- Decide ABI and user-visible behavior.
- Review all changes affecting paging, privilege transitions, interrupts, and
  filesystem corruption risk.
- Run manual QEMU tests and approve acceptance criteria.
- Keep architecture notes and document intentional limitations.

** AI responsibilities

- Explore existing interfaces before changing them.
- Make small, isolated changes and add focused tests where possible.
- Never change the syscall ABI, executable format, or on-disk format without
  human review.
- Report exact files changed, commands run, warnings, and unresolved risks.
- Do not remove unrelated worktree changes or generated files.

** Definition of done for every task

- Code builds with the repository toolchain.
- QEMU behavior is tested when the task affects boot or kernel runtime.
- Failure paths are checked, especially malformed input and allocation failure.
- The task includes a short test note in the commit or review description.

* Suggested Execution Order

1. Human approves console, syscall, ELF, and calculator specifications.
2. AI completes keyboard queue and console line input.
3. AI implements a kernel test process and ring-3 transition.
4. AI and human freeze the syscall ABI.
5. AI implements syscalls and user libc.
6. AI implements the read-only filesystem API.
7. AI implements the static ELF loader.
8. AI builds and launches a trivial user program such as =hello=.
9. AI implements and launches =/bin/calc=.
10. Human performs QEMU acceptance testing and reviews security boundaries.
11. AI implements the shell.

* Risks and Non-Goals

- Do not begin with dynamic linking or kernel module loading.
- Do not share the kernel address space as the application's only memory model.
- Do not enable preemption before interrupt entry and locking are reliable.
- Do not let user programs call kernel internals directly.
- Do not reclaim pages until ownership and failure cleanup are explicit.
